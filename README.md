# Representational similarity and predictive performance across encoder-decoder architectures for geospatial semantic segmentation

Aaron E. Maxwell†, Sarah Farhadpour†, and Christopher A. Ramezan

† Equal contribution

> The paper is currently under review. Citation details will be added upon publication.

## Abstract

Within geospatial semantic segmentation, this study asks whether similarity between feature maps generated by different encoder-decoder architectures using varying combinations of convolutional neural network (CNN), Transformer, and Mamba components implies comparable performance. Centered kernel alignment (CKA) and the Mantel test indicate high similarity among decoder-block feature maps and final feature representations, respectively; however, model performance varied: Mamba-based architectures generally achieved the highest validation F1-scores. When used as inputs to traditional machine learning (ML) classifiers, Mamba-based features generally yielded the highest macro-averaged F1-scores. Reducing the feature space from 96 to 15 variables via different feature reduction methods achieved performance comparable to the full feature space. When all 480 feature maps from the five architectures were combined, Mamba-based features were found to be most important. Further, deep learning (DL)-based methods can serve as a means of generating data abstractions for use in traditional ML workflows.

## Architectures

| Name in code | Encoder | Decoder |
|---|---|---|
| `UNet` | CNN (ResNet-34) | CNN |
| `SwinUNet` | Swin Transformer | Swin Transformer |
| `SwinUNetC` | Swin Transformer | CNN |
| `MambaUNet` | Mamba (VSSM) | Mamba (VSSM) |
| `MambaUNetC` | Mamba (VSSM) | CNN |

Data: [LandCover.ai](https://landcover.ai.linuxpolska.com/) (classes: background, building, woodlands, water, road).

## Repository structure

```
.
├── Training.ipynb          # Train the five architectures
├── Assessing.ipynb         # Evaluate the trained models on the test set
├── CKA_Calculator.ipynb    # CKA similarity between decoder-block feature maps
├── getFMs.ipynb            # Sample final feature representations (96 per model) to CSV
├── MLModels.R              # RF/SVM classifiers on extracted features, feature reduction

    ├── HybridModels/                       # SwinUNetC and MambaUNetC architectures

    ├── CKA_Calculator_main/                # CKA implementation
    ├── Mamba-UNet-main/                    # Swin-UNet / Mamba-UNet code, mamba and causal-conv1d sources

```

## Setup

**Python** (3.11; a CUDA GPU is required for the Mamba-based models):

```bash
pip install torch torchvision torchmetrics albumentations opencv-python pandas numpy rasterio \
            matplotlib seaborn tqdm yacs timm einops huggingface-hub safetensors pillow \
            packaging ninja triton transformers

# Build the Mamba CUDA extensions
cd main-codes/Mamba-UNet-main/causal-conv1d && pip install . && cd ../../..
cd main-codes/Mamba-UNet-main/mamba && pip install . && cd ../../..
```

**R** packages for `MLModels.R`: `tidyverse`, `tidymodels`, `data.table`, `randomForest`, `factoextra`, `micer`, `cowplot`, `bundle`, `permimp`, `FactoMineR`, `vegan`.

**Pretrained encoder weights** (needed by `Training.ipynb`): download into `main-codes/Mamba-UNet-main/code/pretrained_ckpt/`

- Swin-T: [swin_tiny_patch4_window7_224.pth](https://drive.google.com/file/d/14RzbbBDjbKbgr0ordKlWbb69EFkHuplr/view?usp=sharing)
- VMamba-T: [vmamba_tiny_e292.pth](https://drive.google.com/file/d/1uUPsr7XeqayCxlspqBHbg5zIWx0JYtSX/view?usp=sharing)

**Data:** download LandCover.ai and run its `split.py` to create the `output/` image chips and the `train.txt`, `val.txt`, and `test.txt` lists.

## Usage

Run the notebooks from the repository root (they import from `main-codes/` using relative paths). Set the empty path variables at the top of each notebook before running:

| Variable | Meaning |
|---|---|
| `INTPUT_DIR` | LandCover.ai folder (containing `output/` and the split lists) |
| `OUTPUT_DIR` / `MODELS_DIR` | Where trained models are saved / loaded |
| `RESULT_DIR`, `OUT_DIR` | Where metrics, plots, and spatial predictions are written |

In `MLModels.R`, set `INPUT_DIR` (CSV files from `getFMs.ipynb`), `OUT_DIR`, and `RDS_PATH`.

Suggested order: `Training` → `Assessing` → `CKA_Calculator` → `getFMs` → `MLModels.R`; `FMsextraction` and `SpatPreds` produce map outputs.
